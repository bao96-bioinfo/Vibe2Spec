# Review handoff

This is a template, not project evidence. Replace placeholders with actual facts. Omit inapplicable optional details rather than inventing them. Keep this brief and link to preserved files instead of pasting their contents or the full conversation.

- **Task and phase:** <current step identity, revision, specification/pre_execution/results, concrete question>
- **Binding contract:** <exact approved specification, decisions, approval provenance, and relevant acceptance references>
- **Current scope:** <workspace, complete assessment snapshot path and digest, permitted external files>
- **Independent actors:** <actual artifact authors, relevant workers, requested reviewer context>
- **Review budget:** <current round; normally at most two rounds per phase; any approved time/read limits and extension provenance>
- **Prepared evidence:** <source/configuration/commands/settings inventory, check definitions, existing run evidence as applicable>
- **Correction baseline:** <preserved same-phase covered review path and digest, or initial review>
- **Exact change:** <before/after file identities or recorded base and head commits; diff location; include new/untracked artifacts explicitly>
- **Prior findings:** <stable code/path pairs, proposed remedies, fresh coverage IDs that assess each remedy>
- **Impact assessment:** <changed dependencies, criteria, callers or shared state; why proposed reuse remains applicable>
- **Inspection packet:** <optional saved packet location; candidate reuse is advisory>
- **Requested return:** <covered/correction review record, all blockers together, optional suggestions separately, actual effort observations>
- **Execution permission:** <review is read-only; extra test execution requires applicable coordinator authorization>

Read the actual material for fresh or affected obligations. Do not spawn reviewers. At the budget limit, return remaining blockers and required next work; do not silently extend the loop or mark unresolved work complete.
