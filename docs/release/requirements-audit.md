## Finding and correction

The assembled documentation initially contained broken local links to excluded development resources, including OpenSpec planning files, test fixtures, the project example, and the repository README. The root skills resolved their direct references, so the existing package test did not detect these deeper links. This conflicted with the requirement to provide usable installed resources.

The assembler now preserves operational guidance and templates as local resources. When packaged documentation refers to an existing repository artifact that is intentionally excluded from the plugin, assembly rewrites that link to its repository source URL. A missing source artifact remains a build error. Source files, including the frozen paired-envelope contract, are unchanged. The package remains independent of OpenSpec and the development test suite. A preflight rejects symbolic staged contents before link rewriting; a second inspection records the final content inventory.

A new recursive test checks Markdown links throughout the installed package. A fresh temporary assembly, including this assessment, resolved all 54 local links available at the time of this assessment. The separate packaging reviewer inspected the change and required the preflight ordering correction described above. The release build must rerun this test after its final documentation is assembled.

## Release conditions and limits

No additional missing core workflow requirement was identified in this assessment. Final delivery still needs the completed dual-runtime suite, paired runtime observations, final package build, archive, and release report that the coordinator was assembling concurrently. Their observed results belong in [release verification](verification.md); this assessment does not substitute for them or declare them passed in advance.

The marketplace observation uses an isolated local catalog. It establishes supported marketplace operations and installed content, not a completed public Git repository installation after publication. The package's documented repository installation route depends on the release contents being pushed. Official directory submission, account approval, and publication are external states and are not claimed.

The independent workflow forward assessment and the installed-helper cross-host checks are complementary evidence. Neither should be described as a complete native conversational run in both clean hosts. The documentation currently states this distinction. Claims in the final README, release report, and listing must preserve it.
